# Ordrum project context

- Local project for the user's Rivstart A1/A2 Ordkort study website and iPhone Home Screen web app. Follow the user's current language.
- Authored web source is `public/`: plain HTML/CSS/JS. `app/route.ts` serves its index; Vinext and the Sites starter provide server routing. `dist/` is generated build output, not editable source.
- Baseline data: 20 chapters, 1,332 cards and 1,065 unique bundled Swedish speech clips. Preserve stable IDs, original Swedish text, chapters, page references, dictionary/audio attribution and all provenance/license files.
- Browser progress uses `ordrum.rivstart.v1`. `public/cloud.js` syncs authenticated snapshots with `/api/progress`. Keep legacy backups readable and preserve unsynced local edits.
- Cloud metadata `ordrum.cloud.v1` retains the merge baseline/revision; account archives use `ordrum.account.<opaque hash>`. Never upload one account's state into another account. Server authorization uses the dispatch identity, never a client-supplied ID; expectedAccountId is a write precondition only.
- `ordrum.cloud.journal.v1` and the main snapshot's `__cloudCommitId` make merges recoverable across interrupted writes. Preserve this marker atomically with progress, but never upload it as learning data.
- `db/schema.ts` and immutable generated `drizzle/` migrations own the D1 schema. Never create or alter tables while handling a request. Local and hosted databases are separate.
- Progress API must remain private/no-store, same-origin, bounded and atomically revision checked. Service workers must not cache API/auth/progress responses.
- Legacy reference only (not used by current frontend or export): `public/local-sync.js` connects the static Mac page through a user-confirmed hosted `/sync-bridge` window. Keep its exact origin, opener and per-tab channel checks. Forward only GET/PUT to the fixed progress endpoint; never forward login tokens or broaden API CORS. Never cache `/sync-bridge` or `sync-bridge.js`.
- Current supported entries are GitHub Pages `https://silunzh.github.io/ordrum/` and the static Mac page. `public/github-sync.js` talks directly only to GitHub API with an explicitly configured fine-grained PAT limited to the independent PRIVATE `silunzh/ordrum-progress` repository; progress never belongs in this public code repo. Revalidate privacy before requests; reject redirects, invalid identities, corrupt envelopes and missing permissions. Keep credentials out of state, backups, logs, URLs, caches, and git. Persist credentials only with explicit browser remember consent; otherwise session only.
- Preserve Contents API file-SHA CAS, revision and authenticated numeric user+repository identity. Keep cloud.js three-way merges and recovery journal. Provider migration requires explicit exact old/new identity authorization, preserving old account archive and unsynced edits; normal account changes remain isolated.
- Publish only Pages using `.github/workflows/pages.yml` and `scripts/export-pages.cjs`. Export excludes legacy local-sync.js/sync-bridge.js, server/db/runtime/progress/backups/credentials. Never change the personal homepage repository, CNAME, root worker scope or unrelated caches. Do not republish the retired Sites service.
- The Node launcher opens `/?launch=<bounded token>`; the static server gives its current JS/CSS matching query strings to bypass old offline-shell files without changing the localStorage origin. Keep canonical `/` unchanged for PWA installation, and never clear learning data or bypass auth routes to refresh the interface.
- Cloud application must refresh open task/notebook views while preserving live filters, selections and focus. Never replace an open editing or confirmation form just because a cloud snapshot arrived.
- Preserve Swedish å, ä and ö distinction, NFC normalization, optional en/ett and current case/punctuation answer rules.
- `npm run dev` runs the full local server with a separate mock account/database; `npm run local` / `node scripts/serve.cjs` / `启动网页.command` runs the static Mac page at 127.0.0.1:8765. The static page uses the same private GitHub transport as Pages. Node >=22.13 is required for the server. Local mock sign-in is supplied by Sites and must never be copied into production authentication.
- Run `npm test` for behavior changes, build with Sites helpers for hosted work, and verify relevant browser flows. Before a production build, run `node scripts/version-pwa.cjs` after the final public asset edit.
- Preserve legacy `.openai/hosting.json` identity as migration history; do not create or publish another Sites instance. Old server/bridge tests remain regression references; current sync tests are `tests/github-sync.test.cjs` and `tests/cloud.test.cjs`.
